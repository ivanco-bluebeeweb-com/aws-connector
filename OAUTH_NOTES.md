# AWS Connector — заметка по аутентификации (OAuth)

Дата анализа: 2026-08-31

## Коротко: OAuth у AWS НЕТ и быть не может

AWS не предлагает OAuth-авторизацию для своих API управления (EC2, S3, RDS,
Lambda, IAM, CloudWatch, Cost Explorer). OAuth как протокол «войти через
браузер» здесь технически неприменим — это не ограничение нашей платформы,
а устройство самого AWS.

## Как устроена аутентификация сейчас

Коннектор использует **Access Key ID + Secret Access Key** (пара ключей IAM)
с подписью запросов по **AWS Signature Version 4** (см. `aws_sigv4.py`):

- Пользователь создаёт в своём AWS: IAM → Users → Create user
  (рекомендуется отдельный пользователь `imperal-connector` с минимальными
  правами), затем Security credentials → Create access key.
- В панели Imperal вводит Access Key ID + Secret Access Key (+ регион).
- Коннектор подписывает каждый запрос ключами локально — секрет никогда
  не передаётся по сети, только подпись.

Источник в коде: `aws_client.py`, `aws_sigv4.py`.

## Есть ли современная альтернатива ключам

AWS предлагает более строгие варианты, но все они требуют инфраструктуры
на стороне пользователя и не подходят для «вставил ключ в панель»:

| Вариант | Почему не подходит для автоматического подключения |
|---|---|
| IAM Roles Anywhere | Требует X.509-сертификаты и настроенный trust anchor в аккаунте пользователя |
| OIDC-федерация / STS AssumeRole | Требует, чтобы Imperal была зарегистрированным IdP в AWS-аккаунте пользователя (ручная настройка роли + trust policy) |
| EC2 Instance Profile / IRSA | Работает только внутри инфраструктуры AWS, не из нашей панели |

## Что автоматизировано, а что — руками

| Этап | Как делается |
|---|---|
| Создание IAM-пользователя и access key | **РУКАМИ** — AWS не выдаёт ключи «по ссылке», это сознательная политика безопасности AWS |
| Ввод ключей в панель | **РУКАМИ** пользователем, один раз |
| Подпись запросов (SigV4) | **АВТОМАТИЧЕСКИ** — коннектор сам, для каждого вызова |
| Ротация ключей | **РУКАМИ** — пользователь создаёт новый ключ и обновляет подключение |

## Вывод

OAuth для AWS невозможен технически — у AWS его просто нет для этих API.
Максимально близкая к «безопасной простоте» практика уже реализована:
отдельный IAM-пользователь с минимальными правами + локальная подпись
запросов. Полностью автоматизировать выдачу ключей нельзя — это
ограничение самого AWS, а не нашей платформы.

ВАЖНО: в этой заметке никогда не хранить реальные ключи/секреты.
