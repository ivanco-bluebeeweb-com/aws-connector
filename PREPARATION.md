## 1. Паспорт приложения

**Название в Marketplace (display_name): «AWS (Amazon Web Services)»**.
Внутренний app_id/папка: `aws-connector`.

**AWS Connector** — коннектор к ключевым сервисным API AWS через
собственную реализацию подписи запросов Signature Version 4 (SigV4).
BYOK: пользователь подключает свою собственную пару Access Key ID +
Secret Access Key (IAM-пользователь или временные STS-credentials) к
своему собственному AWS-аккаунту. Imperal ничего не хостит и не
проксирует помимо самого подписанного HTTP-запроса.

**Сознательно вне охвата в v1:** AWS — не единый продукт, а несколько
сотен независимых сервисов. Полное покрытие невозможно и не нужно.
Домен v1: **EC2** (инстансы, security groups, volumes), **S3** (buckets,
objects, listing), **RDS** (instances, snapshots), **Lambda** (functions,
invoke, logs), **IAM** (users, roles, policies — read + safe write),
**CloudWatch** (metrics, alarms, logs), **Cost Explorer** (расходы,
прогнозы, разбивка по сервисам). Вне охвата: EKS/ECS (контейнерная
оркестрация — отдельная кандидатская категория), VPC advanced networking,
Route53/CloudFront (DNS/CDN — не входит в operational core), SageMaker/AI
сервисы, специализированные аналитические сервисы (Athena/Glue/EMR).
Это тот же принцип, что у GitLab CI/CD (сознательно не весь GitLab) и
Salesforce (объекты, а не весь AppExchange).

## 2. Проблема в человеческих словах

Когда **DevOps-инженер или облачный архитектор в enterprise-компании**
сталкивается с необходимостью **быстро проверить состояние инфраструктуры,
расходы или права доступа через естественный язык** (а не переключаться
между AWS Console, CLI и десятком открытых вкладок), ему приходится
**вручную заходить в консоль AWS, искать нужный сервис, регион, ресурс**,
из-за чего возникают **потеря времени на рутинную навигацию, риск
посмотреть не тот регион/аккаунт, и невозможность быстро получить
агрегированный ответ (например "сколько мы тратим на EC2 в этом
регионе за последний месяц") без открытия Cost Explorer отдельно**.

**Запрет соблюдён:** формулировка начинается с роли и события, а не с
технологии SigV4.

## 3. Целевой пользователь

DevOps/SRE-инженер, облачный архитектор, FinOps-специалист в компании
среднего/крупного размера, уже использующей AWS как основную облачную
платформу. Вторичная аудитория — CTO/технический руководитель, которому
нужен быстрый агрегированный отчёт по расходам и здоровью инфраструктуры
без обращения к инженерам.

## 4. Границы данных и разрешения (AWS IAM)

BYOK с максимально высоким потенциальным риском (Access Key может иметь
полный доступ к инфраструктуре клиента). Auth & Credentials Standard
применяется в самой строгой форме:

- На экране подключения — явная рекомендация создать выделенного IAM-
  пользователя с **read-only managed policy** (`ReadOnlyAccess` или
  точечные `AmazonEC2ReadOnlyAccess`/`AmazonS3ReadOnlyAccess`/
  `AWSCostExplorerReadOnlyAccess` и т.д.) для базового сценария.
- Explicit warning, если введённый ключ обнаруживает admin/full-access
  права при первой diagnostic-проверке (`sts:GetCallerIdentity` +
  пробный listing) — предупредить, а не заблокировать (ключ мог быть
  осознанно выдан с широкими правами).
- Деструктивные операции (остановка/терминация EC2-инстансов, удаление
  S3-объектов, изменение IAM-политик) — Ярус 3, требуют явного
  подтверждения на уровне UI (confirm modal), а не auto-execute.

## 5. Регион — обязательный параметр

Нет единого глобального endpoint (кроме IAM/STS/Route53/CloudFront).
Каждый запрос идёт на `https://<service>.<region>.amazonaws.com`.
Форма подключения обязана спрашивать регион по умолчанию (например
`us-east-1`), с возможностью переключения региона в самом интерфейсе
(аналогично multi-region паттерну, если такой уже есть в портфеле —
иначе это первый прецедент "региональности" как первоклассного параметра
навигации, не только подключения).
